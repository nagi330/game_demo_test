# 10 · 技能模型与状态系统

> 状态：**已定**。本文件是 `core` 规则引擎的直接实现依据。

## 1. 技能模型

所有人物卡的技能归入三类：

| 类型 | 英文 | 触发方式 | 消耗 | 典型归属 |
|---|---|---|---|---|
| **主动技** | `active` | 玩家主动使用 | 统率值 | 谋臣 |
| **触发技** | `trigger` | 满足条件自动触发 | 免费 | 武将、兵种 |
| **光环** | `aura` | 持续生效，条件满足时 | 免费 | 主公、武将 |

### 1.1 主动技

| 项 | 规则 |
|---|---|
| 使用时机 | 行动阶段 |
| 消耗 | 统率值（0–3） |
| 频率 | 每回合 1 次（默认） |
| 被震慑 | **不能使用** |
| 被混乱 | **可以使用，但目标随机**（在合法目标中） |
| 目标 | 按技能定义的选择器 |

### 1.2 触发技

| 触发时机 | 标识 | 说明 |
|---|---|---|
| 入场 | `on_play` | **上场**后立即触发（俗称"战吼"）。⚠️「上场」有三条路径：**从手牌打出**、**升变**（ADR-114 补）、**被效果召唤**（ADR-121 补）—— 三处都必须派发。改动前只有"从手牌打出"，于是升变出来的宿卫虎士拿不到披坚、召唤出来的黄巾兵不会按统领成长 |

> ⚠️ **升变路径的结算顺序（ADR-127）**：换形态 → 重算光环 → **派发新形态的 `on_play`（抉择按 `action.modeIndex` 选分支）** → 再重算光环 → **最后**判定"新形态拥有先攻则返还一次普攻"。
> 先攻的返还**必须在战吼之后**：有些形态的先攻不是卡面关键词，而是战吼当场用 `apply_status: xian_gong_status` 授予的（陷阵营「陷阵」形态）；放在战吼之前判定，就会出现"同一个形态，打出来的能再打一次、升变来的不能"。
| 阵亡 | `on_death` | 死亡结算后触发（「忠义」「遗计」） |
| 受到伤害 | `on_damaged` | 每次受到伤害后触发 |
| 回合开始 | `turn_start` | 己方回合开始阶段 |
| 回合结束 | `turn_end` | 己方回合结束阶段 |
| 攻击时 | `on_attack` | 发起普通攻击时 |
| 被攻击时 | `on_defend` | 成为攻击目标时 |

### 1.3 光环

| 项 | 规则 |
|---|---|
| 生效条件 | 拥有者存活且条件满足 |
| 影响范围 | 按定义（自身 / 全体友方 / 特定兵种 / 特定列） |
| 重算时机 | 入场、死亡、羁绊变化后立即重算 |
| 与状态的区别 | 光环不产生"状态"，只是动态修正 |

## 2. 技能定义字段

```yaml
skills:
  - id: some_active_skill      # 示例用（别和真卡 id 混：tactic_caochuanjiejian 是卡级效果）
    name: 示例主动技
    kind: active                # active | trigger | aura
    cost: 2                     # 仅 active
    frequency: once_per_turn    # once_per_turn | unlimited | once
    target:                     # 选择器，见 13-balance-data-model.md
      side: ally
      filter: { type: strategist }
      count: 1
    condition: {}               # 可选
    effects:
      - action: draw
        value: 2
    modes:                      # 可选：抉择（二选一），见 13-§7.11
      - name: 分支甲
        effects: [ ... ]
      - name: 分支乙
        effects: [ ... ]
```

> **抉择**（ADR-071）：有 `modes` 时 `effects` 被忽略，由 `PLAY_CARD.modeIndex`
> 选中一个分支执行；缺省 / 越界一律取 `modes[0]`（AI 与测试的兜底路径）。

## 3. 状态全集

### 3.1 增益状态

| # | 状态 | 效果 | 叠加 | 持续 | 关键时机 |
|---|---|---|---|---|---|
| 1 | **振奋** | 攻击 +N | 层数叠加 | 永久或指定回合 | 攻击结算时 |
| 2 | **急救** | 回合开始恢复 N 点生命 | 层数叠加 | 永久 | 回合开始 |
| 3 | **架盾** | 全局嘲讽（仅前军生效） | 不叠加 | 条件性 | 目标选择时 |
| 4 | **先攻** | 先结算伤害，目标阵亡则不受反击 | 不叠加 | 永久 | 伤害结算 |
| 5 | **奇袭** | 不能被指定为攻击目标 | 不叠加 | 攻击后失去 | 目标选择时 |
| 6 | **伤害免疫** | 免疫一次伤害 | 不叠加 | 消耗后失去 | 伤害结算前 |
| 7 | **护甲** | 吸收伤害（**仅主将**） | 层数叠加 | 永久 | 伤害结算前 |
| 13 | **守护** `shou_hu` | **被守护单位**受到的伤害转给来源单位 | 不叠加 | N 回合 | 伤害结算前 |
| 14 | **护主** `hu_zhu` | **只有该方主帅**受到的伤害转给来源单位 | 不叠加 | 由光环维持 | 伤害结算前 |

> 「守护 / 护主」的差别只在**范围**：两者都靠 `redirect_damage` 能力 + `srcUid`
> 找到替他挨打的人。状态定义里用 `guard_scope: any | lord` 区分（ADR-071）——
> 陈宫「忠烈」是 `any`（被指定的友军挨打时他接），祖茂「替主」是 `lord`（只护主帅）。

### 3.2 减益状态

| # | 状态 | 效果 | 叠加 | 持续 | 关键时机 |
|---|---|---|---|---|---|
| 8 | **震慑** | 不能普通攻击、不能使用主动技 | 不叠加 | N 回合 | 攻击声明 / 技能使用 |
| 9 | **混乱** | 普通攻击与主动技的目标**在合法目标中随机** | 不叠加 | N 回合 | 目标选择时 |
| 10 | **灼烧**（`zhuo_shao`） | 该方**回合开始时**受 N 点**火攻**伤害（N = 层数）。**来源：对敌方释放的火攻效果各 +1 层**（ADR-134），与伤害数值无关 | 层数叠加、**不封顶** | **永久** | **回合开始**（该方回合的第一步） |
| 10b | **中毒**（`zhong_du`） | 该方**回合结束时永久降低 N 点生命上限**（N = 层数；**不造成伤害**） | 层数叠加、**不封顶** | **永久** | 回合结束 |
| 11 | **虚弱** | 攻击 −N | 层数叠加 | N 回合 | 攻击结算时 |
| 12 | **断粮** | 统率值上限 −N | 层数叠加 | N 回合 | 回合开始 |
| 13 | **水困**（`shui_kun`） | **只有该单位主动行动**（普攻 / 主动技）时才受 **2^(阶段-1)** 点**水攻**伤害（阶段 1/2/3/4 → **1/2/4/8**，**无上限**）；**不行动 = 完全不受伤** | 层数叠加＝**阶段**，**不封顶**；重复施加**取较大者、不降级** | **永久** | **行动时**；阶段在该方**回合结束 +1** |

> **三系 debuff 的时机刻意错开**（ADR-132）：**回合开始＝灼烧（火）／行动时＝水困（水）／回合结束＝中毒（毒）**。
> 三者惩罚的行为各不相同 —— 火罚「存在」（站着就掉血）、水罚「行动」（动就掉血）、毒罚「拖」（拖越久耐久越少），
> 完整对照与理由见 §3.2.4。

> **灼烧的时机（ADR-132 改判）**：原定"回合结束"，设计者最终定案为**该方回合的最开头** ——
> 早于统率回满、抽牌与一切行动。理由：灼烧伤害**完全可预期**（层数即伤害、徽章上就写着数字），
> 所以"先烧后动"不构成零交互；而把它与中毒挤在同一个时点，两种"掉血 / 掉上限"会混在一起看不清。
> 实现见 `mutate.resolveTurnStartDamage`（由 `engine.startTurn` 在函数最开头调用）。

> **灼烧的来源（ADR-134 全局规则）**：**对敌方释放的火攻效果各 +1 层** —— 挂在**效果层**
> （`effects.ts` 的 `case 'damage'`：`damage_type === 'fire'` 且目标阵营 ≠ 施法方），
> **不在伤害管线里按属性判断**。三条推论必须记住：
> 1. **每次火攻效果各 +1 层、与伤害数值无关**（蒙冲斗舰「蒙冲」对敌 3 段 → 3 层；3 点段也只 +1 层）；
> 2. **打自己人 / 自身不挂层**（设计者原话「释放的火攻只对敌人」）—— 蒙冲第 4 段是"对自身 2 点火伤"，
>    只掉血、不挂层；施法者永远不会因自己的火攻中灼烧；
> 3. **DoT 跳伤本身不计**（灼烧的跳伤也是火属性，若按属性挂层会**每回合自我叠层、无限增长**）；
>    火攻被减到 0（披坚 / 免伤 / 藤甲减伤）**仍然挂层** ——「火攻打出去了」即挂；
>    挡得住挂层的只有既有的"不可选中"与 `immune_debuff`（发 `STATUS_BLOCKED`）。
>
> **⚠️ "永久"指的是状态定义，也指现在每一次施加**（ADR-134 起）：`zhuo_shao` 的
> `duration: permanent` 意思是**不写 `duration` 的施加永不自然到期**（只能被净化）。
> 三张老火卡（荀攸 / 陆逊 / 董卓）**曾经**各自在 `apply_status` 上给了更短的**实例时长**
> （1/1/2 回合，ADR-116 的逐次施加口径）；ADR-134 已把它们全部删除，**灼烧一律永久**
> —— 荀攸/陆逊的显式施加整体删掉（火伤自带 1 层，再写就是双倍），
> 董卓改走**方案乙**（对敌方全体男性 1 点火攻，由全局规则挂层）。
> 水困与中毒同样是彻底永久（ADR-132）。

> **水困**的完整规则见 §3.2.2；**中毒**见 §3.2.3；**三系的时点节奏**见 §3.2.4。

> **⚠️ ADR-117 改名**：上表第 10 行原先叫**中毒**（`zhong_du`），但卡池里**只有三张火卡在用它**
> （荀攸「乌巢袭粮」/ 陆逊「策火流云」/ 董卓「暴虐」），卡面写的也一直是「灼烧」——
> 名字与语义对不上。现拆成两个状态：**火 → `zhuo_shao`（灼烧）**，
> **`zhong_du` 回收给真正的毒**。引用 `zhong_du` 的旧文案/文档一律按「灼烧」读。
> （那三张火卡现在都**不再显式施加**灼烧 —— 见上面的 ADR-134 来源说明。）

### 3.2.1 守护类状态的持续时间（ADR-089）

`守护`（陈宫「忠烈」）这类**转移伤害**的状态写在**被守护者**身上，而它是在
**施法方自己的回合**施加的 —— 若按常规在自己回合末递减，它会在对手回合开始前消失，
而对手回合正是它唯一有意义的时段。因此这类状态用 `duration: until_next_turn`：
施加当回合跳过第一次递减，从下一次起正常计时。见 `13-balance-data-model.md` §7.1。


### 3.2.2 水攻体系：行动税（ADR-116 立项，ADR-132 重做）

**火**（`zhuo_shao` 灼烧，ADR-117 前叫 `zhong_du`）与**水**（`shui_kun` 水困）是两条**正交互补**的持续轴。

#### 对照表

| | 火 · 灼烧（`zhuo_shao`） | 水 · 水困（`shui_kun`） |
|---|---|---|
| 时点 | 该方**回合开始**（回合的第一步） | 该单位**主动行动**时（普攻 / 主动技结算之后） |
| 效果 | 受 N 点**火**伤（N = 层数） | 受 **2^(阶段-1)** 点**水**伤：阶段 1/2/3/4 → **1/2/4/8**，**无上限** |
| 不作为的代价 | 每回合照掉（惩罚"存在"） | **0**（不行动 = 完全不受伤） |
| 持续 | **永久** | **永久**（ADR-132 起；旧口径"1~2 回合随费用"已作废） |
| 叠加 | 层数累加、**不封顶** | 层数＝**阶段**、不封顶；重复施加**取较大者、不降级** |
| 惩罚的玩家行为 | **「存在」**（站着就掉血） | **「行动」**（动就掉血） |
| 解法 | 解状态 / 速杀 | **少动**（不行动那一回合就是 0 伤）＋ 净化 |

#### 为什么这样设计（而不是"水 = 又一个 DoT"）

1. **决策轴不同**：火惩罚"存在"、水惩罚"行动" —— 玩家面对两者时的**取舍完全相反**。
   被灼烧 → 想尽快解掉或速杀；被水困 → 面临"动就掉血 vs 不动丢节奏"的两难。
2. **曲线形状不同**（两者都永久，但一个是直线、一个是翻倍）：
   ```
   水困（目标每回合行动 1 次，阶段每回合 +1）    灼烧 1（永久，每回合开始烧 1）
     回合1：阶段1 → 行动 1 伤                       回合1: 1
     回合2：阶段2 → 行动 2 伤                       回合2: 1
     回合3：阶段3 → 行动 4 伤                       回合3: 1
     回合4：阶段4 → 行动 8 伤                       每回合稳定 1 点，不封顶
     合计 15 伤 / 4 回合，且继续翻倍
   ```
   水困是 **1+2+4+8+…** 的几何级数，且**全部由"玩家自己决定行动"产生** —— 设计者明确接受
   「第 5 回合 16 点，**前提是他行动**」。
3. **水有解、火没有**（ADR-132 改口径后依然成立）：不行动就完全不受伤 ——
   被水困的单位这一回合什么都不做，那一回合的水伤就是 **0**；灼烧却是"站着也掉血"。
   两者的取舍依然相反，这是水困强度可控的根本原因。

#### 行动税的四条硬约束（ADR-132 修订）

| # | 约束 | 理由 |
|---|---|---|
| 1 | 只由**主动行动**触发（普通攻击 / 主动技） | **不包括**反击、触发技、光环 —— 那些不是"玩家的选择" |
| 2 | **不设每回合上限** | 连击 / 强制攻击单位本就越强，水困正好是它的克制（连击打两次 = 收两次税） |
| 3 | ~~固定 1 点~~ → **2^(阶段-1)、无上限** | ADR-132 改判：设计者接受成倍曲线，代价是"必须行动"；不行动则 0 伤 |
| 4 | **升变不算行动** | 升变（`UPGRADE_UNIT`）既不是普攻也不是主动技，不收税 |

#### 阶段的推进与"不降级"

- **施加当回合为阶段 1**；在该方**回合结束时 +1**（`stage_up` 能力），此后每回合 +1，**不封顶**。
- **层数＝阶段**：卡面减益徽章直接显示 `stacks`（`card-render.js`：`stacks > 1` 时拼在名字后），
  所以**徽章上的数字就是阶段**，玩家能自己算出"这次行动要挨几点"。
- **重复施加取较大者、不降级**（`StatusDef.stack_mode: 'max'`，ADR-132 新字段）：
  若按累加，同一张 2 费卡连发两次就能把阶段顶到 4（行动一次掉 8 点）；
  而"再施加一次反而让阶段倒退"更反直觉。故 `max(旧阶段, 新施加)`。

#### 引擎实现要点

- 两个能力（cap）都挂在 `shui_kun` 上，引擎**只查能力、不认状态 id**：
  · `damage_on_action` —— `attack()` / `useUnitSkill()` 两处，在行动**结算完成后**扣税，
    扣 `2^(该状态的层数-1)` 点 `water` 伤害（逐状态取自己的层数，不是能力的层数总和）；
  · `stage_up` —— `resolveTurnEndStatuses` 在回合末把层数 +1。
- 扣税排在行动**之后**：让玩家先完成这次行动再吃税，避免"因为被水困所以这次攻击没了"的挫败感；
  单位若已阵亡（如被反击打死）则不再扣（`u.hp <= 0` 保护）。
- 伤害类型统一传 `'water'`。⚠️ 水攻强化 `water_damage` 的加成在**发起伤害侧**结算
  （`effects.ts` 的 `damage` 动作），行动税直接调 `dealDamage`，**不经手它**（现状如此，未变更）。

### 3.2.3 毒攻体系：削生命上限（ADR-117 立轴，ADR-132 重做）

> 载体：无当飞军「毒箭」（蜀 · 弓兵 · 3 费 · 0/2，战技每回合一次，**指定**一名敌方单位）。

火、水之外，**毒**是第三条持续轴。三条轴**惩罚的玩家行为各不相同**，
这是它们能并存而不重复的全部理由：

#### 三轴对照

| | 火 · 灼烧（`zhuo_shao`） | 水 · 水困（`shui_kun`） | **毒 · 中毒（`zhong_du`）** |
|---|---|---|---|
| 时点 | 回合开始 | 行动时 | **回合结束** |
| 效果 | N 点**火**伤 | 2^(阶段-1) 点**水**伤 | **永久降低 N 点生命上限**（**不造成伤害**） |
| 持续 | **永久** | **永久** | **永久** |
| 叠加 | 层数累加、不封顶 | 层数＝阶段、不封顶、取较大者 | 层数累加、**不封顶** |
| 惩罚的行为 | **「存在」**（站着就掉血） | **「行动」**（动就掉血） | **「拖」**（拖越久耐久越少，且**不可逆**） |
| 解法 | 解状态 / 速杀 | **少动** / 净化 | **净化**（只能止住，已削的不恢复）/ 速杀毒源 |
| 目标池 | 单位 | 单位 | **单位（不含主公）** |

#### 削上限的五条细则

| 项 | 规则 |
|---|---|
| 削多少 | N = 层数；该方**每个回合结束各削一次**，逐回合累计 |
| 夹紧 | 削完若**当前生命 > 新上限** → 夹到新上限（**不低于 0**） |
| 不造成伤害 | 当前生命 ≤ 新上限时**原地不动** —— 削的是"这一局的耐久"，不是"当前这一条命" |
| 上限归零 | 上限降到 0 → 当前生命夹到 0 → 按引擎既有约定（`hp <= 0` 即阵亡）结算 |
| 净化的边界 | 净化**停止**继续削，但**已削的不恢复**（削减记在单位的永久属性修正层里，不随状态删除回滚） |

#### 主公免疫（ADR-117 决定，ADR-132 复核后**仍然有效**）

中毒**只作用于场上单位**：`毒箭` 的选择器是 `filter: { type: 'character' }`、
**不写** `include_lord`，因此敌方只剩主公时**没有任何合法目标**（测试钉死）。
依据 GDD 12 规则一「单次随机 / 无解效果不得决定胜负」—— 一条**不可逆**的削上限落到
30 血主将身上，会变成不需要攻击的自动胜利线。

#### 历史：为什么不再是"回合末 N 点毒伤、封顶 3、2 回合"

ADR-117 的旧口径是"回合末受 N 点毒伤、层数封顶 3、每次施加把时长重置为 2 回合"。
ADR-132 把它整个换成**削上限**，理由：**"每回合掉 N 点血"与灼烧重复**（只是伤害属性不同），
而**削上限是独一无二的** —— 它惩罚"拖"，且因为不可逆，越拖越难翻盘。

设计者原案（续毒既加时又加伤 → 二次增长 1/3/6/10/15，主将 8 回合必死）的教训仍然保留：
**同一次「续毒」动作不能既给时长又给伤害**。新口径下续毒只给"每回合多削 1 点"，
且没有时长可加（永久）。

旧口径留下的两项资产：

- `StatusDef.max_stacks`（施加时夹紧层数）**保留在引擎里**，但当前**没有任何状态在用** ——
  三系 debuff 全部不封顶（中毒的 `max_stacks: 3` 已随 ADR-132 删除）；
- 第 4 种伤害属性 `poison` **保留**：它仍是「毒箭」那 1 点直伤的属性，
  `reduce_physical` 只作用于 `physical`，所以**藤甲挡箭不挡毒**（1 点毒伤照扣，1 点物理被减成 0）。

#### ⚠️ "剧毒"不在本文内

`ju_du`（剧毒）是**独立关键词**，与本节的「中毒」是两件事：它的定义是
**该单位造成伤害并实际命中后，直接消灭受伤目标**。无当飞军**不再携带它**（见 GDD 06 §3.12）。

### 3.2.4 三系的时点节奏：火（回合开始）→ 水（行动时）→ 毒（回合结束）

> ADR-132 定案。三系 debuff 的时机**刻意错开**，让玩家一眼分清挨的是哪一种。

| 时点 | 系 | 发生什么 | 玩家能做什么 |
|---|---|---|---|
| **回合开始**（该方回合第一步，早于统率回满 / 抽牌 / 任何行动） | 火 · 灼烧 | 受 N 点火伤（N = 层数） | 回合开始前就要算好：1 血单位带灼烧会**直接阵亡、本回合无法行动** |
| **行动时**（普攻 / 主动技结算后） | 水 · 水困 | 受 2^(阶段-1) 点水伤；**不行动 = 0** | 可以选择"这回合不动"来完全规避 |
| **回合结束**（该方回合末） | 毒 · 中毒 | 永久削 N 点生命上限（不造成伤害） | 只能净化（止住）或在此之前解决毒源 |

**为什么三条轴不在同一个时点**：三个效果挤在同一步时，飘字、结算顺序与玩家的注意力全部叠在一起，
"到底挨了哪一种"变得不可读；拆成三个时点后，每个时点只发生一件事，因果清晰。

**为什么灼烧是"回合开始"而不是"回合结束"**（设计者最终定案）：灼烧伤害**完全可预期**
（层数即伤害、徽章上就写着数字），所以"先烧后动"不构成零交互 —— 玩家仍有一整个回合去净化、
去速杀、或用这个单位去换掉对面；反过来把它放在回合末，它就和中毒挤在同一时点，
"掉血"与"掉上限"两种后果混在一起看不清。

> **同一回合末的顺序（只剩两条）**：① **中毒**削上限（`shrink_max_hp`）→ ② **水困**阶段 +1（`stage_up`）。
> 二者互不影响，但引擎仍分**两趟**跑，顺序与状态在对象里的插入顺序无关。
> ⚠️ 旧要求的"同一步内先灼烧（伤害）→ 再中毒（削上限）"**已作废** —— 灼烧改到回合开始后，
> 两者不再处于同一时点。

### 3.3 叠加规则

| 类型 | 规则 |
|---|---|
| **数值型**（振奋/急救/灼烧/**中毒**/**水困**/虚弱/断粮/护甲） | 默认按**层数累加**（2 层振奋 = +2 攻击；2 层灼烧 = 回合开始掉 2） |
| **数值型 + `stack_mode: 'max'`**（目前只有**水困**） | 层数＝**阶段**，重复施加**取较大者、不降级**（ADR-132）—— 连续施加不该让阶段倒退 |
| **标志型**（架盾/先攻/奇袭/伤害免疫/震慑/混乱/守护/护主） | **不叠加**，只判定"存在与否" |
| 同名标志型重复施加 | 刷新持续时间，不叠加效果 |
| 层数上限 `max_stacks` | 声明了就**在施加时**夹紧；当前**无状态声明**（三系 debuff 都不封顶） |

### 3.4 震慑的具体限制

| 行为 | 是否允许 |
|---|---|
| 普通攻击 | ❌ |
| 主动技 | ❌ |
| 触发技 | ✅（被动仍生效） |
| 光环 | ✅ |
| 被攻击 | ✅ |
| 反击 | ✅（被攻击时仍会反击） |

### 3.5 混乱的具体规则

| 项 | 规则 |
|---|---|
| 影响范围 | 普通攻击、主动技 |
| 目标选择 | 在**合法目标集合**中随机（仍受架盾、同列等规则约束） |
| 无合法目标 | 该行为无法执行（不消耗统率） |
| 是否影响触发技 | ❌ |

## 4. 结算时机表（核心）

> 这张表是 `core` 的实现规范。任何卡牌效果都必须挂在以下某个时机上，不允许"任意时刻"。

| 序 | 时机 | 触发内容 | 顺序细则 |
|---|---|---|---|
| **0** | **回合开始的最前** | **灼烧结算**（`dot_fire` 能力驱动） | **ADR-132**：该方回合的**第一步** —— **早于**第 1 步的统率回满、第 2 步的抽牌、以及该方**任何行动**。伤害 = 层数 N、火属性、永久、不封顶。1 血单位会在此**直接阵亡**（本回合无法行动）。灼烧伤害事件排在 `TURN_START` 事件**之前**（测试钉死）。**层数来源（ADR-134）**：**对敌方释放的火攻效果各 +1 层**（挂在效果层，不在伤害管线）—— 跳伤本身不叠层 |
| 1 | 回合开始 | 完整回合结束时双方上限 +1（≤10）；本回合统率值回满 | ADR-061 |
| 2 | 回合开始 | 抽 1 张牌 | 牌库空 → 粮尽伤害 |
| 3 | 回合开始 | 回合开始类效果 | ① 急救回血 ② 光环重算 ③ 断粮修正（作用于下回合上限） |
| 4 | 出牌 | 检查统率是否足够 | 含断粮修正后的上限 |
| 5 | 出牌 | 消耗统率值 | — |
| 6 | 入场 | 入场触发技 | 按卡牌定义的顺序 |
| 7 | 入场后 | **羁绊重算** | 检查全部羁绊，授予/移除增益 |
| 8 | 攻击声明 | 合法性检查 | ① 是否被震慑 ② 攻击次数是否用完 ③ 是否当回合入场 ④ 是否被自己人挡住 |
| 8½a | 攻击声明后 | `on_attack` 触发技 —— **非击杀条件**那部分 | **排在算攻击力之前**（ADR-071）：姜维「文武双全」/魏延「桀骜不驯」写的是"攻击时攻击力 +1"，触发技若排在伤害之后，这一下吃不到加成（还会因为没写 `duration` 而永久累积）。触发技把攻击者自己弄死 → 本次攻击取消 |
| 8½b | 伤害交换之后 | `on_attack` 触发技 —— **`condition.event: killed`** 那部分 | **ADR-072**：击杀与否只有伤害结算完才知道。位置有两个硬约束：① 排在**整个伤害交换之后**（攻击者被反击打死则不拿奖励）；② 排在**本回合攻击次数 +1 的记账之后**（否则关兴「额外行动」刚清零就被加回去）。`killed` 只指**这一击**，不跨攻击残留 |
| 8½c | 伤害交换与攻击次数记账之后 | `after_attack` 触发技 | 攻击者存活时结算；`condition.event: damaged` 只认可本次普通攻击实际造成伤害，免疫或完全吸收不触发（ADR-117） |
| 9 | 攻击声明 | 目标选择 | ① 架盾优先级 ② 同列/跨列规则 ③ 混乱时随机 |
| 10 | 伤害结算前 | 免疫判定 | 伤害免疫状态 → 消耗并免疫；其他免疫效果 |
| 11 | 伤害结算前 | 护甲吸收 | 仅主将；护甲归零后剩余伤害进入下一步 |
| 12 | 伤害结算 | 先攻判定 | ADR-055：先攻只表示"入场当回合即可攻击"；ADR-062：反击**同时结算**，打死目标也照吃反击 |
| 13 | 伤害结算 | 造成伤害 | 攻击力 = 面板 + 振奋 − 虚弱 |
| 14 | 伤害结算 | 反击 | 无双/先攻例外；主将不反击 |
| 15 | 伤害结算后 | 饮血回血 | 为主将恢复等量生命（≤30） |
| 16 | 伤害结算后 | 受到伤害触发技 | `on_damaged`；己方主公实际扣血后触发己方单位 `on_lord_damaged`，反射伤害不递归触发（ADR-117） |
| 17 | 死亡结算 | 移出战场 | 血量 ≤ 0 |
| 18 | 死亡结算 | 亡语触发 | 忠义 / 遗计 |
| 19 | 死亡结算后 | **羁绊重算** | 羁绊可能失效 |
| **行动后** | 普攻 / 主动技**结算完成之后** | **水困行动税**（`damage_on_action` 能力驱动） | **ADR-116/132**：只由**主动行动**触发（**不含**反击、触发技、光环、**升变**），受 `2^(阶段-1)` 点水属性伤害（阶段 = 层数；1/2/4/8…，**无上限**）。在行动**结算完成后**扣（单位已阵亡则不扣）；**不设每回合上限**（连击打两次收两次税）。伤害事件排在这次行动的伤害/死亡事件之后 |
| 20 | 回合结束 | 回合结束类效果 | ① **中毒削生命上限**（`shrink_max_hp`：永久 −N，N = 层数，不造成伤害）② **水困阶段 +1**（`stage_up`，施加当回合为阶段 1）③ `turn_end` 触发技。⚠️ 灼烧**已不在此步**（见第 0 步）；两步都为**能力驱动**，分两趟跑、顺序与状态插入顺序无关 |
| 21 | 回合结束 | 清除临时效果 | "本回合"类增益/减益 |
| 22 | 回合结束 | 手牌上限检查 | >10 张则弃至 10 张 |
| 23 | 回合结束 | 交出行动权 | — |

## 5. 交互边界（必须实现的用例）

| # | 场景 | 正确结果 |
|---|---|---|
| 1 | 有「先攻」的攻击者攻击有「伤害免疫」状态的目标 | 攻击者先造成伤害 → 伤害免疫状态抵消该次伤害 → 目标存活 → **目标反击** |
| 2 | 「无双」攻击者攻击有「先攻」的目标 | 攻击者造成伤害 → 无双跳过反击 → 目标若存活仍会反击？**否**：反击属于被攻击方，无双免除的是攻击者受到的伤害，因此目标不反击 |
| 3 | 「混乱」人物攻击，场上存在「架盾」 | 在**架盾人物集合**中随机选择目标 |
| 4 | 后军的盾兵 | **失去架盾**，不再强制敌方目标选择 |
| 5 | 盾兵同时拥有「奇袭」 | **不允许共存**（会导致架盾死锁），见 §6 |
| 6 | 攻击力在声明后、结算前发生变化 | 按**攻击声明时**的场面判定 |
| 7 | 羁绊加成导致血量变化后羁绊失效 | 血量最低保留 1 点（**待确认**，见 `09-bonds.md` §6.1） |
| 8 | 中毒（或灼烧）人物在结算前被击杀 | **不再结算** —— 灼烧在第 0 步（回合开始）就结算完，中毒在回合末结算时会跳过已阵亡的单位 |
| 9 | 「震慑」人物被攻击 | 仍会正常反击 |
| 10 | 主将被「震慑」 | 无效（震慑只作用于人物卡） |
| 11 | 带灼烧的 1 血单位轮到它行动 | **回合开始即阵亡**（第 0 步），本回合**无法行动**（攻击请求被拒） |
| 12 | 被水困的单位整回合不行动 | 该回合受 **0** 点水伤（与灼烧/中毒的关键区别），但阶段仍在该方回合末 **+1** |
| 13 | 被水困的单位在一回合内攻击两次（连击） | **收两次税**（不设每回合上限），各按当时的阶段算 |
| 14 | 中毒把生命上限削到 0 | 当前生命夹到 0 → 按 `hp <= 0` 的既有约定**阵亡** |
| 15 | 中毒后又被净化 | 停止继续削，**已削的不恢复**（不可逆） |
| 16 | 水困重复施加（阶段已 3，再施加 1 层） | 阶段**保持 3**（取较大者、不降级），不会退回 1 |
| 17 | 火攻伤害被免伤 / 披坚 / 藤甲减到 **0** | **仍然挂 1 层灼烧**（ADR-134：「火攻打出去了」即挂） |
| 18 | 火攻打**自己人 / 自身**（蒙冲斗舰第 4 段自损 2 点） | **不挂层**（设计者口径：释放的火攻**只对敌人**）；伤害照常结算 |
| 19 | 同一张卡多段火攻，其中一段把目标打死 | 该段**不给已离场的单位挂层**；其余各段照常各挂 1 层 |
| 20 | 范围火攻（陆逊 / 火烧洛阳）命中主公 | 主公照吃**当次**火伤，但**不吃灼烧层** —— `dot_fire` 只在回合开始遍历**场上单位**，挂了也不会跳伤 |
| 21 | 带 2 层灼烧的单位连续 3 个回合结束回合 | 每个回合开始各烧 **2** 点，**层数始终是 2**（DoT 跳伤不计入挂层） |

## 翻面（ADR-059 定稿）

| 项 | 规则 |
|---|---|
| 效果 | 被翻面的单位**当回合不能行动**（不能普攻、不能用主动技），**不能被指定为目标**（含计策） |
| 解除 | **该单位自己的下个回合开始时**翻回正面，当回合即可正常行动 |
| 表现 | 战场上显示为**卡背**；不显示攻血/技能/状态标记 |
| 用途 | 保护性（吕蒙「白衣渡江」把自己和友方翻面规避打击，下回合再行动） |

> **与"召唤失调"的区别**：召唤失调是新入场当回合不能**攻击**（仍可用技能、仍可被指定）；
> 翻面是完全不能行动**且**不能被指定。
