# 18 · 人物技能设计方法论

> **本文是"帮设计者构思/重做一张三国人物卡"的标准流程。**
> 触发场景：设计者说「帮我设计 XXX 的技能」「这个人物技能好不好」「重做一下 XXX」。
> ⚠️ **硬性要求：任何一次人物技能设计，都必须交付「1 个最推荐 + 3~5 个备选」。**
> 只给一个方案 = 没做完（设计者要的是**可挑选的余地**，不是替他拍板）。
>
> 相关文档：`13-balance-data-model.md`（基准尺与效果 DSL）、`12-randomness.md`（三条随机性铁律）、
> `14-open-questions.md`（ADR 决策表）。

---

## 0. 一句话总纲

> **先考证、再评判、后发散；发散要给"1 推荐 + 3~5 备选"，每个方案都要标清
> 史料等级、引擎成本、强度估算、对手能否对冲。**

人物卡的设计不是"想一个酷炫效果"，而是**把史料翻译成机制，再用项目的尺子量一遍**。
跳过任何一步都会产出"给谁都能用"的白板，或者"注释承诺了、代码没实现"的假效果。

---

## 1. 第一步：考证（不可跳过）

**派考证代理**（本仓库标准做法），产出 `docs/research/<人物>.md`，结构照 `docs/research/shu-zhaoyun.md`：
§0 结论先行 / §1 史料分布与卷次 / §2–§6 分主题 / §7 与卡池角色关系 /
§8 正史 vs 演义对照 / **§9 陷阱清单** / **§10 未找到原文** / **§11 可翻译成机制的特征清单**。

**铁律**：

| | |
|---|---|
| **四档分级** | **A**＝《三国志》正文／**B**＝仅裴注或他书／**C**＝仅演义·戏曲·民间（明清）／**D**＝近现代创作（影视、游戏、网络） |
| **不许编造** | 查不到就写「**未找到原文**」。**绝不拼句**——本仓库已出过事故：把相隔 5 年的两句缝成「维不答书，而敛兵聚谷」，原文里根本不存在（ADR-158 附记） |
| **不许拿现代辞书当出处** | 汉典等已发现有**失引** |
| **网络取原文** | 维基文库要**走代理**：`curl -s -m 45 -x http://127.0.0.1:7799 "https://zh.wikisource.org/w/index.php?title=三國志/卷NN&action=raw"`；演义用 `三國演義/第NNN回`（三位补零）；`insource:"词" prefix:三國志` 可做全站检索定级 |
| **⭐ 多版本对勘** | 维基文库 65 卷本有**系统性繁简讹字**（已实测：「將士**鹹**怒」应作「咸」、「郭**循**」应作「郭脩」、监本误「亡水」应作「芒水」）→ 重要引文用四库本对勘 |

**「陷阱清单」与「未找到原文」是产出的一部分，不是附录。**
不写这两节，等于把"我以为是的"当成了"史书说的"。

## 2. 第二步：评判现有设计（若已有卡）

逐条过一遍，**每条都要给数字或原文**：

| 检查项 | 怎么查 |
|---|---|
| **身体偏差** | `属性点 = 攻 + 血`，`基准 = 2 × 费用 + 1`，差值记为 −N。**−N 就是这条技能必须撑起的价值** |
| **人物指向性** | ⭐ 反问：**这个技能换给另一个同阵营的人，成立吗？** 成立 = 白板，必须重做 |
| **死机制** | 条件是否可达？`condition` 里有没有写在 `count`/`exists`/`count_vs` **后面**被静默忽略的字段？（见 `17-troop-system-rework.md` §三个通用落地坑） |
| **状态挂对了吗** | 例：封**主公技**要用 `jin_yan`（caps `block_lord_skill`），挂 `jin_yong` 不生效 |
| **假效果** | 卡面写的能力，状态定义里真的有吗？例：`mian_yi` 只能免 debuff 与指定，**不免疫伤害** |
| **数据形态** | 技能有 `kind`/`trigger` 吗？`effects` 的**缩进**对不对（缩到卡牌层会被静默当成卡牌级效果）？ |
| **flavor 与 note** | 空着吗？引文标级了吗？ |
| **合规** | 过一遍 `12-randomness.md` 三条 + 非法关键词组合（架盾 + 奇袭） |

⭐ **最有效的单条判据是"人物指向性"**。本仓库的真实案例：
- 姜维旧版「文武双全（策略）」＝"打出战法牌就抽牌" → **给任何谋臣都成立**
- 庞统旧版「凤雏之智」＝"非人物牌 −2 统率" → **给任何谋臣都成立**
- 马谡旧版「搞意」＝"抽 2 弃 2" → **与马谡零关联**（而他真正的名句是「攻心为上」）

## 3. 第三步：发散（**1 推荐 + 3~5 备选**）

### 3.1 交付格式（硬性）

```
## 最推荐：〈技能名〉
- **史料**：原文＋卷次＋等级
- **机制**：一句话能说清玩家做什么、发生什么
- **引擎**：零改动 / 需补 X（按铁律先改 13-balance-data-model.md）
- **强度**：身体偏差 −N 对应技能值 M，合计 ≈ 基准
- **对冲**：对手怎么拦
- **为什么最推荐**：一句话取舍

## 备选 B / C / D / E
（同格式，但可以更简短）
```

### 3.2 发散的五个方向（每次至少覆盖三个不同方向）

**不要在一个方向上微调数字** —— 那不算备选。五个可用的方向：

| 方向 | 做法 | 本仓库先例 |
|---|---|---|
| **① 把史料里的"动作"直接机制化** | 史书里他**做过什么事**，就做成那个动作 | 姜维「诡说会」→ `take_control` 策反 |
| **② 把史料里的"评价"数值化** | 别人怎么评价他 → 数值/条件 | 赵云「一身是胆」→ 敌人越多越猛 |
| **③ 把史料里的"两难"做成抉择** | 史书里的分岔（上中下三策、进还是退）→ `modes` 二/三选一 | 曹彰「猛袭」是唯一先例 |
| **④ 把史料里的"结局"做成亡语/反转** | 他怎么死的 → 阵亡时的效果 | 黄皓「覆国」、关平「遗计」 |
| **⑤ 用史料里的"关系"做联动** | 与卡池已有角色的关系 → `card_id` / tag / 羁绊 | 关平↔关羽、马岱↔西凉系 |

⭐ **优先挑"全池还没有的动作"**（如"拒绝响应""多选一""按已阵亡查询"）。
但**必须先核引擎是否支持** —— 见第 4 步。

### 3.3 参考其他游戏（可做灵感，但**必须隔离**）

可以看《三国杀》《三国志战略版》等怎么处理这个人物，但：

- ⚠️ **另起一节，标题写明「非史料，仅玩法参考」**
- ⚠️ **绝不可写进卡面 `note`**（那是史料区）
- ⚠️ 它们的效果往往**违反本项目的随机性铁律**（如"50% 直接消灭"）→ 借**思路**，不借数值

---

## 4. 第四步：核引擎（决定方案能不能落地）

每个备选都必须标 **引擎成本**，并**先查再写**：

| 要查什么 | 怎么查 |
|---|---|
| 效果动作是否存在 | `core/src/effects.ts` 的 `case '...'`；动作清单见 `10-skills-statuses.md` |
| 触发器是否存在 | `trigger` 全集（`on_play`/`on_death`/`on_kill`/`on_attack`/`on_damaged`/`on_defend`/`on_lethal`/`on_lord_damaged`/`on_mark_death`/`on_mark_damaged`/`turn_start`/`turn_end`/`on_action`/`on_card_played`） |
| 条件是否存在 | `core/src/types.ts` 的 `Condition`；写法见 `13-balance-data-model.md` §② |
| 过滤器是否存在 | `TargetSelector.filter` 的字段集 |
| ⚠️ 有没有**兜底陷阱** | `mode: 'choose'` 在"所选目标不在池子里"时会**兜底命中第一个合法目标**（`effects.ts:638`）→ **不能用选择器去"试探"所选目标的属性**，要用 `chosen_*` 条件 |
| ⚠️ 条件的**求值时机** | `condition` 是**结算到那一条效果时**求值的，不是技能开始时 → 需要"开始时"的语义就要**快照**（见 `chosenDamagedAtStart`，ADR-159） |

**若必须改代码**：按铁律 ①③ —— **先改 `13-balance-data-model.md`，再改代码**，并在 `14-open-questions.md` 记 ADR。

⚠️ **能零改动就别改引擎**（复用现成动作往往比新造更优雅）—— 例：姜维的"立即获胜"**没造"获胜"动作**，
而是复用「对敌方主公造成 9999 伤害 → `checkWinner`」。

## 5. 第五步：过合规与设计原则

| 检查 | 出处 |
|---|---|
| **随机性只决定过程、不决定胜负** | `12-randomness.md` 规则一。判据：单次随机结果的极端情况，不应直接导致一方失败 |
| **随机性必须可读** | 规则二。判据：用这张卡前，玩家能说出**所有可能的结果范围**。❌「随机一个效果」 |
| **随机性有上下限** | 规则三。伤害浮动 ≤ ±20%；随机目标须在合法集合内 |
| **可读、可对冲** | `12-randomness.md` 与 GDD 12 的两条设计原则：对手**看得见**、**拦得住** |
| **非法关键词组合** | 架盾 + 奇袭 |
| **卡名 ≤ 4 字、技能名 ≤ 4 字**（允许「XX（阵亡）」式后缀）；必须填 `memo` | `AGENTS.md` 命名约定 |

⭐ **"公开判胜技"这类极端效果的合规姿势**（ADR-160 姜维「复汉」为范例）：
**零随机 ＋ 条件苛刻且完全公开 ＋ 留出至少一个对手回合的反制窗口 ＋ 可被盾/免伤挡下。**

---

## 6. 第六步：交付与验证

设计交付必须附带：

1. **`note` 写清出处与等级**，并列出「**不得写**」清单（该人物的常见误传）
2. **`flavor` 用 A/B 级原文**（宁缺毋滥 —— 但**空着是最差的选择**，本仓库 16 张旧蜀将 flavor 为空）
3. **测试**：数据形态 + 行为（含边界与反制）＋ **变异验证**（注入变异必须变红）
4. **若动了引擎**：GDD 先行 + ADR + `npm test && typecheck && validate && verify:dsl && smoke`
5. **报告给设计者**：改了什么、为什么、涉及哪些文件、建议的提交粒度

---

## 7. 速查清单（每次设计前扫一眼）

- [ ] 考证稿写了吗？§9 陷阱与 §10 未找到原文齐吗？
- [ ] 现有设计的**身体偏差 −N** 算了吗？
- [ ] 反问过「**这技能换给别人成立吗**」吗？
- [ ] 给了 **1 推荐 + 3~5 备选**吗？覆盖了**至少 3 个不同方向**吗？
- [ ] 每个备选标了 **史料等级 / 引擎成本 / 强度估算 / 对冲方式**吗？
- [ ] 查过**引擎到底支不支持**吗（动作、触发器、条件、过滤器、兜底陷阱、求值时机）？
- [ ] 过了一遍 **`12-randomness.md` 三条铁律**吗？
- [ ] 其他游戏的参考**隔离**了吗（不进 `note`）？
- [ ] `note` 里有「不得写」清单吗？`flavor` 是原文吗？
- [ ] 测试与**变异验证**做了吗？

## 附：本仓库已有的反面教材（都是真事，别再犯）

| 事故 | 教训 |
|---|---|
| 马超「铁骑突袭」写 `turn_max: 1` | 6 费卡**第 1 回合打不出来** → 条件**数学上不可达**，技能从未触发过 |
| 马超封主公技挂 `jin_yong` | 该状态只封**单位**主动技；封主公技要 `jin_yan`。**改对了条件也没用** |
| 赵云「一身是胆」挂 `mian_yi` | 该状态**不免疫任何伤害**，卡面「免疫一切伤害」一直是假的 |
| 草船借箭承诺"每阵亡一个武将抽 2 张" | 当时引擎**没有"谁死过"的记录** → 效果从未生效，最后**改卡面**绕开（后由 ADR-160 的 `fallen` 补上） |
| 黄忠「百步穿杨」第一版 2 点不含主公 | **严格劣于一张 2 费特种兵**（先登弩手：2 费、指定 2 点、含主公）→ **不做横向比对就会做出倒挂** |
| 黄忠条件不做快照 | 技能自己先打出的伤害把目标变成"受伤" → 条件**恒真**，"满血 3 点"退化成"必定 4 点" |
| 庞统引用「维不答书，而敛兵聚谷」 | **拼接句，原文不存在**（两段相隔 5 年、语境相反） |
| 「一计害三贤」当成正史 | 实为**演义**（《三国志传》明刊本庙赞「美（姜维）一計害三賢」）→ 用可以，**必须标 C** |
